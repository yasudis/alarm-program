# Alarm Program — Release E2E Checklist

Используйте этот чеклист перед публикацией релизной сборки.

## 1. Подготовка сборки

- [ ] Выполнить restore/build в конфигурации Release.
- [ ] Сформировать publish через профиль `ReleaseSingleFile.pubxml`.
- [ ] Убедиться, что в output присутствует единый exe и сопутствующие файлы.

## 2. Установка на чистой машине

- [ ] Скопировать релизный output на чистую Windows 10/11 машину.
- [ ] Запустить приложение от обычного пользователя.
- [ ] Проверить старт окна и отсутствие критических ошибок в логе при первом запуске.

## 3. Настройка каналов

- [ ] Ввести валидные Telegram `Bot Token` и `Chat ID`.
- [ ] Включить Telegram, сохранить настройки.
- [ ] Нажать кнопку «Тестовая отправка» и дождаться сообщения в чате.
- [ ] (Опционально) Ввести Discord webhook, включить канал и проверить тестовую отправку.
- [ ] (Опционально) Ввести HTTPS webhook URL, включить канал и проверить JSON POST.

## 4. Проверка сценариев событий

- [ ] Проверить уведомление о Startup после запуска приложения.
- [ ] Проверить уведомление о Shutdown (корректное выключение).
- [ ] Проверить уведомление о Restart.
- [ ] Проверить уведомление о Unexpected shutdown (если воспроизводимо в тестовом стенде).
- [ ] Проверить, что одинаковые события не дублируются в коротком временном окне.

## 5. Перезапуск и фоновый режим

- [ ] Перезапустить приложение и убедиться, что фоновой мониторинг снова активен.
- [ ] Проверить паузу/возобновление мониторинга из UI.
- [ ] Свернуть в трей и убедиться, что приложение остается активным.
- [ ] Включить автозапуск и проверить старт после перезагрузки Windows.
- [ ] Перезагрузить ПК и проверить сообщение о предыдущем shutdown/restart событии.

## 6. Диагностика и безопасность

- [ ] Проверить rolling-лог и наличие CorrelationId / контекста ошибок отправки.
- [ ] Открыть каталог логов кнопкой «Открыть логи».
- [ ] Убедиться, что токены/секреты не сохраняются в открытом виде в `settings.json`.
- [ ] Проверить, что при неверных настройках UI показывает валидационные ошибки и не сохраняет значения.
- [ ] Проверить журнал последних алертов в главном окне.
- [ ] Очистить журнал кнопкой «Очистить журнал» и убедиться, что список пуст.
- [ ] (Опционально) Включить watchdog процесса и убедиться, что ProcessDown приходит при остановке процесса.
- [ ] (Опционально) Проверить RDP connect/disconnect.
- [ ] (Опционально) Включить watchdog службы и проверить ServiceDown.
- [ ] (Опционально) Подключить/отключить USB и проверить алерты.
- [ ] (Опционально) Нажать «Повторить outbox» при наличии queued сообщений.
- [ ] (Опционально) Задать JournalRetentionDays и убедиться, что старые записи удаляются.
- [ ] (Опционально) Включить ping-watchdog хоста и убедиться, что HostUnreachable приходит при недоступности.
- [ ] (Опционально) Включить HTTP health-check и проверить HttpEndpointDown.
- [ ] Проверить фильтр журнала по типу/теме.
- [ ] Проверить, что heartbeat содержит IP, uptime и диск.

## 7. Финальная верификация

- [ ] Повторно выполнить тестовую отправку из UI.
- [ ] Проверить, что релизная версия/файловая версия соответствует ожидаемой (`1.0.0.0`).
- [ ] Зафиксировать результаты проверки и список известных ограничений.
