# PROMPT FOR NEW AGENT

Ниже готовые промпты, которые можно вставлять новому агенту, чтобы он продолжил проект в том же стиле и по уже созданным документам.

---

## Вариант 1: Мягкий режим (с подтверждением после каждой задачи)

```text
Работаем над проектом Alarm Program (Windows, C#).

Перед началом обязательно прочитай файлы:
1) alarm_programm/idea alarm_programm.md
2) alarm_programm/plan_alarm.md
3) alarm_programm/architecture_alarm_csharp.md
4) alarm_programm/backlog_alarm.md

Правила работы:
- работай строго по архитектуре и backlog из этих файлов;
- не придумывай новую архитектуру, если нет явной проблемы;
- реализуй задачи по порядку, начиная с P0;
- после каждой задачи останавливайся и жди моего подтверждения.

Формат ответа после каждой выполненной задачи:
1) Что сделано (кратко и по делу)
2) Какие файлы изменены
3) Как проверить локально
4) Какие риски/ограничения остались

Технические требования:
- C# / .NET (актуальная стабильная версия)
- WPF + DI + слоистая архитектура
- логирование и обработка ошибок обязательны
- минимум лишнего кода и лишних зависимостей
- не добавляй фичи вне текущей задачи

Сейчас начни со Sprint 1:
A-01 -> A-04, затем B-01 -> B-03.

Начни с A-01.
```

## Вариант 2: Автономный режим (несколько задач подряд)

```text
Работаем над проектом Alarm Program (Windows, C#).

Сначала обязательно прочитай:
1) alarm_programm/idea alarm_programm.md
2) alarm_programm/plan_alarm.md
3) alarm_programm/architecture_alarm_csharp.md
4) alarm_programm/backlog_alarm.md

Твоя цель: последовательно реализовать задачи Sprint 1 без ожидания подтверждения после каждого шага.

Порядок задач:
1) A-01
2) A-02
3) A-03
4) A-04
5) B-01
6) B-02
7) B-03

Правила:
- строго придерживайся архитектуры из architecture_alarm_csharp.md;
- не меняй структуру проекта без необходимости;
- не добавляй функции, которых нет в текущих задачах;
- при неоднозначности выбери практичный вариант и коротко обоснуй;
- если блокер критичный — остановись и запроси решение.

После завершения всех задач одним сообщением дай отчет:
- список выполненных задач;
- список измененных/созданных файлов;
- команды для проверки/сборки;
- что осталось на следующий спринт.
```

## Вариант 3: Точечный промпт на одну задачу

Используй, когда хочешь дать агенту ровно одну задачу из backlog.

```text
Прочитай:
- alarm_programm/architecture_alarm_csharp.md
- alarm_programm/backlog_alarm.md

Выполни только задачу: <ВСТАВЬ ID, например D-02>.

Требования:
- реализуй только scope этой задачи;
- не трогай несвязанные части проекта;
- добавь минимальные проверки (или тесты, если уместно);
- после выполнения дай отчет:
  1) что сделал,
  2) какие файлы изменил,
  3) как проверить,
  4) что может сломаться.
```

## Вариант 4: Режим код-ревью (поиск багов и рисков)

Используй, когда уже есть код и нужно проверить качество реализации перед следующим этапом.

```text
Проведи code review текущей реализации Alarm Program.

Перед началом прочитай:
1) alarm_programm/idea alarm_programm.md
2) alarm_programm/plan_alarm.md
3) alarm_programm/architecture_alarm_csharp.md
4) alarm_programm/backlog_alarm.md

Затем проверь код проекта с фокусом на:
- соответствие архитектуре и слоям;
- корректность работы с Event Log;
- устойчивость отправки уведомлений (ошибки, retry, таймауты);
- безопасность хранения секретов (token/chatId);
- логирование и диагностируемость;
- потенциальные race conditions / дубли событий;
- готовность к следующему этапу backlog.

Формат ответа:
1) Findings (сначала критичные, потом средние, потом низкие)
2) Для каждого пункта: проблема -> где -> риск -> как исправить
3) Что обязательно исправить перед продолжением разработки
4) Что можно отложить на post-MVP
5) Короткий итог: готово ли текущее состояние к следующему спринту

Важно:
- не ограничивайся стилем кода, ищи именно поведенческие и архитектурные риски;
- если не нашел проблем, явно напиши, что серьезных проблем не найдено, и укажи остаточные риски/пробелы в тестах.
```

## Рекомендация по использованию

- Если работаешь итеративно и хочешь контроль: **Вариант 1**.
- Если хочешь быстрее пройти каркас: **Вариант 2**.
- Если хочешь точечные правки: **Вариант 3**.
- Если нужно проверить качество и риски перед следующими задачами: **Вариант 4**.

---

## Мини-чеклист перед запуском нового агента

1. Убедись, что все 4 базовых файла существуют в `alarm_programm/`.
2. Выбери режим (мягкий / автономный / точечный).
3. Вставь промпт без изменений (или измени только список задач).
4. После первого ответа агента проверь, что он действительно прочитал файлы и идет по backlog.
